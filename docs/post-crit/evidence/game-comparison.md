## Primary rules and package checks

Accessed22October2026. [Hasbro's original-mode instructions](https://instructions.hasbro.com/en-ca/instruction/connect-4-game-instructions) establish the two-player dropping/four-in-row game and42pieces. This spike uses a generic7x6 gravity board with original presentation. The [Bicycle Crazy Eights rules](https://bicyclecards.com/how-to-play/crazy-eights/) supply the five-card deal, rank/suit matching, wild-suit choice and stock exhaustion basis. We declare no recycling, blocked-all-players draw and no match scoring as bounded house policies. These sources establish rules, not enjoyment or expected round duration.

[FIDE2023 Laws](https://handbook.fide.com/chapter/e012023) concern over-the-board play and distinguish claimable versus automatic draws; they do not certify this online fixture. Three minutes each/no increment allows at most six combined minutes of running clocks. The spike automatically accepts chess.js draw detection as a disclosed house policy, and labels timeout adjudication unresolved because insufficient-material detection does not cover every FIDE mating-possibility situation. [chess.js1.4.0 manifest](https://github.com/jhlywa/chess.js/blob/v1.4.0/package.json), [licence](https://github.com/jhlywa/chess.js/blob/v1.4.0/LICENSE) and actual installed package agree on BSD-2-Clause. Its ESM code is107,052bytes, served uncompressed in the fixture. It supplies legal moves/history/terminal helpers; it does not supply clocks, authority, UI or multiplayer reliability. Full notice retained in the spike directory.

The exact runtime is Linux Node24.21.0, pnpm11.9.0, project Playwright1.63.0, sandboxed Chromium153.0.8010.12 using the declared1243 executable and SwiftShader. Package setup is task-local; repository root manifests/lock were not changed. Initial pnpm install selected the containing workspace and installed nothing; the reproducible setup uses `--ignore-workspace`. No settings or sandbox bypass was introduced.

## Bounded recommendation and selection conditions

Keep four-in-a-row as the provisional low-surface route when a drop-in two-player break with four spectators is acceptable. Its measured phone actions are large, public state stays compact, and there are no hidden hands or clocks. That is a maintainability tradeoff, not evidence that friends prefer it or that42moves guarantee3–6minutes.

Choose chess if the actual group values that ritual/depth enough to justify authoritative clock/timeout/restart policy and a bounded public history projection. The phone target miss is repairable shared spacing, not grounds for rejecting chess. Choose cards if all-six active participation matters more: the measured actor projections exclude all hidden cards/deck, but production shuffle, private transport, large hands and departures remain real added work. Do not build multiple production tables to defer the decision. Parent/Astra owns selection after evidence review; group preference is absent.

Before any production game, resolve one consent/start state, whether closing a panel only watches or resigns, leaving the lounge, disconnect versus departure, table expiry, membership removal, reconnect/rejoin/replacement, restart/downtime clocks and a leave retry that remains valid after the actor moves to a bedroom. Fixture leave ends any round with `member-left`; it is not an approved house policy. Lost ACK and member removal need actual authority/transport/transaction tests. Secure Fisher–Yates shuffle, no hidden deck in any event/receipt/log, and revoked-member access require production checks for cards. A fixed timestamp fixture and context booleans do not verify these boundaries.

The [final scoped source manifest](game-source-manifest.json) records exact bytes/lines/hashes. Shared engine6,652B and UI app6,448B are compact fixture code, not per-candidate maintainability scores. Four needs board/turn/result and move/leave actions; chess adds initial-position/history, clocks, promotions and adjudication; cards adds hands/stock/discard suit/pass tracking and play/draw/pass actions. The matched fixture shell imports chess.js for all three candidates, so it does not establish per-candidate production transfer cost. Four/cards rules themselves do not require that package. No dependency was added to the root application.
