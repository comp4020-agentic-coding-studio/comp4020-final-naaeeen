## Component and consent

`public/house-puzzle-ui.js` is a plain DOM component inside the existing break panel. Its fixed 24 destination buttons and fixed 24 described piece buttons survive updates; the tray exposes 12 per page. The accepted original illustration is one full board background beneath opaque unsolved covers. Selection uses outline/check and text, and reference content describes the scene. Tap-piece then tap-place and roving arrow/Home/End navigation share the same controls. No drag is needed. Shared chat uses the existing movable window and actual transcript.

Only accepted `live.puzzleRoster` supplies participation. Start captures a durable start body; it never invokes Join. Direct ACKs supply feedback and do not enroll. Uncertain direct events expose original retry. Leave starts a newer direct withdrawal before Return invokes navigation. A local withdrawal blocks further placement immediately and survives same-authority unjoined snapshots followed by a delayed joined roster. Only a fresh explicit Join or authority/round change releases that local withdrawal guard. Final completion leaves the picture visible and releases live consent through backend projection.

Fresh placements capture the participation UUID. Wrong placement preserves selection. A peer solving the selected piece clears selection without removing focus. Round/context changes clear selection; late old replies cannot replace a new choice. A separate durable flight token prevents Leave from trapping the component in busy state when an older placement later settles.

An unfinished reset opens an explicit owner confirmation only when no other active participant is present. The confirmation stores the original full table revision/round, roster epoch/revision and authority. Ordinary roster updates never rebase it; the server must reject a changed roster. An authority replacement cancels the confirmation. Initial or completed replacement captures at click. Pending durable actions remain in the existing inspector/export path, with readable puzzle action labels.

## Return and work continuity

The break return callback begins withdrawal of the actual active/pending activity and closes the tool immediately, including when the resident is watching the other table. If seated it requests Stand and waits for the accepted unseated snapshot before calling the existing `routeTo('room')`; movement intent cancels a waiting/deferred journey. Returning from another bedroom uses the existing exit/lounge route. Own-room arrival offers the room panel with a separate Open my work action when no newer panel/workspace is open. A failed route opens My work immediately when it would not replace a newer explicit tool. No desk is required.

A compact SAVED HOUSE-VISIBLE WORK section at the top of the room panel shows `currentCard()` goal/next step. It does not display unsaved form values. Open my work preserves existing newer drafts. Desks continue to open the viewer's same house-visible card. Entry, movement and return do not change willingness, door permission or card completion.
