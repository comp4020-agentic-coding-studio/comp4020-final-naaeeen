# 夜间居民区：实际验证、比较与评审记录

2026-10-06。这里报告研究工作中真正做过的检查，不是正式A3应用的验收报告。主结论：**小场景固定视角真实3D可在网页里运行；共造灯的工程规则可行；产品价值与正式部署仍需验证。**

## 比较是怎样声明的

- [原始协议](visual-comparison-protocol.json)在原型结果观察之前写入；三候选是相同内容的固定正交3D、有限轨道/透视3D、不同插画资产的SVG等距草图。
- [测量补充](measurement-amendment.json)在探索/修复之后、正式矩阵采样之前声明环境、顺序和指标。探索已经发生，不能说矩阵是完全未见条件的第一次试验。
- 1920×1080与390×844，各候选三次读取diagnostics；3D为近一秒滚动窗口，SVG仅有一次约180帧的聚合完成值。重复的早期SVG读取保留，**不算三次独立样本**。
- firstPageSceneReadyMs切视图后仍保留初次页面值，不作为各候选的导航加载时间。sceneReadyMs从renderer factory开始，排除了动态模块获取；SVG还包含其明确的两次RAF就绪过程，不进行夸大倍数排名。

## 原型与资产的真实边界

安装Three.js **0.186.1**；本地Node24.15.0、npm11.12.1；Codex内置桌面浏览器，本地warm-cache场景，GPU型号和精确浏览器版本未记录。脚本使用任务内npm cache，没有改全局配置。公开GitHub资产通过Node fetch读取；PowerShell读取曾出现TLS认证失败，没有禁用TLS。

采用作者KayKit仓库固定commit `96d5930a8dbdb363409bbc2d3341718b00e17c9c`，8文件总 **62,941字节**，包括3模型、匹配缓冲、共享纹理与CC0许可。模型三角形分别为chair308、table168、lamp320；实际场景两把椅子加桌/灯，共4个模型实例。其余房屋/固定装饰、植物、住户、共同灯是程序几何。[实际资产清单](../prototypes/visual-comparison/assets/kaykit/ASSET-MANIFEST.json)

后端是本地HTTP+SSE与原子重命名JSON，显式Alice/Bob供实验。客户端可自行填写actor，**不是生产认证**。没有安装生产Socket.IO、better-sqlite3或部署Fly；JSON重启检查不证明断电/卷损坏耐久性。

## 有效浏览器矩阵

原始文件保留完整取样：[browser-matrix.json](browser-matrix.json)。以下仅摘录有效条件，不把小样本当统计性能结论。

| 候选 | 有效视口与内部场景 | 本地观察 | 限制 |
| --- | --- | --- | --- |
| Fixed3D桌面 | 1920×1080；场景CSS1088×620；内部544×310；DPR1 | 3模型loaded；235draw calls、11,632计数三角形；CPU render约0.97–0.98ms | 计数含渲染pass，CPU不等于GPU完成/余量 |
| Orbit3D桌面 | 相同 | 同235/11,632；CPU约1.15–1.21ms | 相机及导航一起改变；不能单独估算orbit作用 |
| SVG桌面 | 1920×1080；场景1088×620 | 428 DOM节点；约180帧RAF聚合 | 不同资产；没有可比GPU三角形或CPU绘制指标 |
| Fixed3D手机布局 | 实核390×844；场景341×330；内部171×165；DPR1 | 同235/11,632；CPU约0.94–0.98ms；无横向溢出 | 桌面模拟，不是手机GPU或触摸 |
| Orbit3D手机布局 | 相同 | 同235/11,632；CPU约1.09–1.15ms | 手势/页面滚动仍须真实设备检查 |
| SVG手机布局 | 390×844；场景341×330 | 428节点；整屋可见；选中轮廓明显 | 插画与3D差异，不能归因于引擎 |

3D读取的RAF节奏约16.68–17.50ms，首次切换窗口存在57–58fps，其他多为约60fps。**RAF回调节奏不是GPU帧时间或正式负载容量**。全部有效矩阵读取的浏览器日志为空，没有观察到未捕获错误；这不是所有失败路径已验证。

最初三次“手机”请求实际仍1920×1080，DOM尺寸检查发现override作用于另一个tab。它们标记 `valid:false`，截图保留为`failed-viewport-*`，随后在新tab确认390×844重新采样。不能把那些失败请求写成手机结果。

原生clip裁剪也出现错误/空白。所有`sceneScreenshot`已明确拒绝，匿名文件原图保留为`rejected-crop-*`；正确比较改用完整原生截图，候选文件因此显示view标签，复审明确是 **不匿名** 的纠错。它不是重新随机化的新盲试。

## 独立比较判断与纠错

第一位比较者使用`fork_turns:none`，只读同一brief和匿名候选图，顺序M/N/P与Q/R/S；第二位顺序相反，但保留先前资产研究与父任务提到共造方向的背景，**不是完全盲的新上下文**。不合并成用户偏好或伪造统计A/B。

两人发现原始裁剪不等价，第一次视觉选择N已撤回。完整截图纠正后，他们都倾向M（Fixed3D），同时认为P（SVG）选择反馈/夜间氛围有优势；这与用户偏好的纵深、网页模型复用和维护判断一起支持固定3D，而不是拿两个模型的票数证明审美。
