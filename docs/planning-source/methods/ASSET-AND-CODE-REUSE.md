# Asset and code reuse method

Before adopting a pack, template or library record the original author/source,
exact version or download, licence text, allowed use and redistribution, attribution,
file formats, size and dependencies. Use original author pages for terms. Do not
infer permission from an aggregator's thumbnail or a free download label.

For art assets inspect actual geometry, textures, scale, orientation, materials,
animation and style consistency in the intended renderer. Record mobile costs and
what was measured. Compare a small representative room before buying or committing
to a large catalogue. Paid purchases require the user's scoped authorization.

For code inspect manifest, runtime behaviour, licence, maintenance and required
services. Reuse a verified existing helper when appropriate; adapt A2 contracts to
Fly and the chosen stack. Keep hard-coded historical paths, hooks and configurations
as disabled references. Do not transfer credentials, caches, private traces or
permission bypasses.

Keep an asset catalogue with stable IDs, semantic category, placement rules,
bounded customization fields, version and migration/deprecation strategy. Store
room choices by IDs, not by embedded untrusted code or mutable external URLs.
Separate the persistent room schema from renderer-specific loading details.

A room's visual language can borrow a mechanism without copying game identity,
characters or unlicensed assets. Preserve provenance and record where our novel
social interaction differs from the reference.
