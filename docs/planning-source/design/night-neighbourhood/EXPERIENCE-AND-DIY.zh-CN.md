# 夜间居民区：体验、交互、美术与 DIY 规格

2026-10-06。下列是推荐的产品规格，除[工程原型](../../prototypes/visual-comparison/README.md)明确展示的部分，尚未实现。

**适用层级：**空间与DIY的丰富配置以Full目标描述；Core只用一个布局、6件地面物品（有余力到12）、一盏共同灯和简易回访。Core不包含欢迎旗、整个纪念档案、墙/桌面槽、第二布局、海报或音频。下表C01/C02/C03/C05/C07/C08属于Core；C04在Core仅有灯片，C06在Core只有保存结果与简易回访。Full扩展不得被写成Core已完成的承诺。

## 空间应该长什么样

**入口**是一栋能一眼看清关系的小楼：约 6–8 扇不同装饰的窗，楼下有共享灯；Full加入欢迎旗。夜色偏蓝紫，窗内是暖光；远景只用简化楼体/轮廓，不建立可以无限行走的城市。用户选择窗或小院，镜头进行短距离过渡；开启减少动态时立即切换。

**个人房间**采用同一方向的切面视角。窗台、墙面、地面提供三个层次，桌面摆件是预定义附着槽；家具可移动而房屋结构固定。主人编辑，朋友参观。始终能从对象列表看见家具名称、位置、归属和可用操作，不让遮挡成为寻找功能的门槛。

**共同小院**不是公共聊天大厅。Full有两个带明确制作规则的物件：共同灯和欢迎旗。公共家具与动线初版由开发者布置，不让所有人争夺同一把椅子。场景可见少量过去留下的东西，文字详情在网页卡片里阅读，不把大段文字强塞到像素招牌上。

一次只加载正在看的完整空间。楼外只绘制简单窗群；进入某个房间时才加载其家具，离开后释放私人几何/材质或保留有界缓存。这能避免“8 个房间 × 30 件”同时变成场景成本。真正的容量需 D11 的真实设备测量。

## 核心能力合同

| ID | 能力与可见结果 | 规则 | 初版验收 |
| --- | --- | --- | --- |
| C01 | 邀请预览、领取窗、再次回来 | 邀请授予居民区成员资格；昵称不是凭据；持久 session/恢复码用于找回本人 | 两个独立 browser context 区分身份；清 cookie 后使用恢复码，不误领旧住户 |
| C02 | 个人窗/房间配色与布置 | 只有房间主人可编辑；保存后提供明确反馈 | 刷新、重新登录与服务器重启恢复选择；其他成员写入拒绝 |
| C03 | 目录选物、移动、旋转、移除、撤销 | 8×8 格、半格步进、90° 旋转、最多 30 件；有限 surface/variant | 边界、固定障碍与物品互相碰撞都由服务器校验；撤销仍检查当前版本 |
| C04 | 给共同灯添自己的部分（旗仅Full） | 每位当前成员有一个 owned contribution；无贡献部分使用中性图案，不出现“缺席者”名单 | 一人先贡献即可成形；另一人小时后接上；作者可改/收起自己的部分 |
| C05 | 自动看见相关变化 | 确认后才称“已保存”；恢复时补齐或重取快照 | 远端无需刷新，目标约 1 秒；断线期间无虚假成功 |
| C06 | 简易回访；命名纪念版仅Full | 回访标记存在本人浏览器，不记录可供朋友查看的最后上线时间；纪念版显式创建 | 后来进入能理解变化；作者撤回后纪念版/详情均不显示旧内容 |
| C07 | 成员管理、退出和内容收起 | 创建者可撤销邀请/移出成员；只能处理自己的内容，管理员不能偷偷改别人房间 | 旧连接再次写入拒绝；房间与作者内容按明确规则撤回；其他作者不受牵连 |
| C08 | 手机、键盘与失败时仍能操作 | 所有核心画布动作有原生控件；加载失败有文字与重试/轻量视图 | 不用拖动完成一次布置/贡献；390×844 无横向滚动；焦点可见 |

生产 `spec/` 应检查这些对用户有影响的合同，不能只是验证当前函数返回值。原型共用小场景/演示身份，不代表 C01、C06、C07 已完成。

## 第一晚与回访的界面

**邀请页面**：说明小楼名称、谁能看见房间/短注释、昵称可否更改、内容如何收起。兑换前不展示成员名单、房间或注释，公开美术预览使用独立合成数据。不要先要求邮箱或第三方账号。浏览器先生成新的高熵恢复码，让用户复制/下载保存，再发送入驻或恢复请求；网络响应丢失时仍有已保存的码和可重试交换。普通草稿存储不保存此码。可以稍后重新生成，使旧码失效。不能承诺“清了浏览器也会自动认出你”。

**领取窗**：优先顺次推荐一个空窗，不要求用户先理解整栋楼的坐标。选择完整头像预设、昵称、窗帘/灯色；一个成功动作后才引导到房间。用户可以跳过美化直接看小院。

**编辑房间**：点击“布置”进入明确模式；平常点击家具打开参观信息。编辑中显示物件名、移动/旋转/移除、保存状态和撤销；离开编辑模式不会悄悄丢弃未确认命令。非法放置保留原位置，说明“这里有书架 / 超出地板”，而不是只显示红色。

**参与共同灯**：对象卡片解释“你可以改变自己的灯片”；给 5–8 个色彩/图案预设和一段至多 140 字符的可选注释。颜色选择产生真正的物件变化，文字用于表达缘由。作者来源按需展开，不在默认场景显示贡献计数/名单排名。

**回访**：在空间里用温和标记指出少数改变，打开“这些地方变了”最多 3–5 条聚合信息，例如“这盏灯多了蓝色的一片”。同一作者连续调色聚合成最终选择。点击即可定位物件；没有改变时直接显示正常空间，不制造通知。

**纪念版（Full）**：任何成员为一个共同物件显式创建一个命名纪念版本，系统从已提交内容创建语义快照。不同晚上可以各自创建；重试同一次创建沿用同一个 occasionId，不重复生成。名字相同不意味着系统知道是同一事件。数量上限、并发与删除规则以 SYSTEM-DESIGN 为准。看旧版本时有清楚的日期和“纪念版”标签，不让人以为自己正编辑实时物件。档案与实时编辑不会共享一个模糊的“保存”按钮。

## 手机与可访问性

桌面可以左侧场景、右侧编辑详情。手机建议采用 **场景上方 + 紧贴所选对象的可展开底部操作面板**，核心控件无需滚完整张长表单。原型现阶段是上下堆叠，虽然操作已能完成，仍需在正式版缩短从看物件到改物件的距离。

- 普通按钮和调色目标至少 44×44 CSS 像素；邻近留空。拖动只是便利入口，方向按钮/坐标步进始终可用。[WCAG 2.2 拖动替代](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。44 是本项目触摸目标，不混淆为 WCAG AA 的 24 像素最低要求。
- 默认固定镜头，手机页面滚动不触发 orbit。若以后增加旋转，进入明确查看模式，并提供复位镜头；编辑和旋转不用同一种没有提示的手势。
- 整个页面保持清晰 DOM 字体，像素化只作用于场景。正文/控件检验实际颜色对比，目标 WCAG AA；高对比主题、对象轮廓和选中名称共同表达状态，颜色不是唯一信号。[WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 键盘顺序：进入空间 → 对象列表 → 当前动作 → 共同物件详情；面板打开聚焦标题/首控件，关闭回到触发点。冲突/失败用克制的 live region，不连续播报每帧/光效。
- 减少动态关闭漂浮、相机滑动、周期粒子；动画不必代表在线。音频默认关闭，用户点启动后才播放，可单独控制音量与暂停。
- WebGL 不可用时，保留对象清单、贡献详情和全部动作；轻量视图可以使用相同语义状态，先用静态插画 + DOM，不必维护第二套复杂引擎。正式 context-loss 与恢复要实测，不能仅凭 catch 分支宣称完成。
- 使用真实手机的 Chrome/Safari 验证触摸、缩放、软键盘、焦点和长昵称。390×844 桌面视口只证明布局的一部分。

## 有限 DIY 如何仍然有表达力

限制应提供可理解的选择，而不是一个只有三个装饰选项的样板间。Full第一批12件目标覆盖 **坐、写、收纳、照明、植物、墙面表达**六类；加上布局、配色、位置/朝向和共同物件就有明显差异。质量允许才扩到 24。

| 维度 | 首版允许 | 可持续扩展 | 不必现在做 |
| --- | --- | --- | --- |
| 空间 | Core固定外壳与1个布局；Full最多2个同方向预设 | 新外壳按 templateId 加入 | 任意拆墙、扩楼、自由高度 |
| 位置 | Core地面半格网格与旋转；Full表面槽位 | 新桌面槽、墙面挂点 | 真实物理、任意缩放、堆叠穿插 |
| 材质 | 经过验证的整件 variant | 拆分材质后增加局部配色 | 对整张 atlas 任意改色 |
| 个人表达 | 昵称、窗色、完整头像预设、摆放 | 像素海报、头像附件 | 原始模型/图片/SVG/脚本上传 |
| 共同表达 | Core灯片与短注释；Full旗块 | 新模板、新贡献结构 | 用户自写“配方代码” |

撤销先作为 **当前会话最后 20 个本人编辑命令** 的反向操作：只在受影响实体 revision 仍匹配时应用；遇到另一个标签页改过则显示冲突，不能越过后来修改。30 件上限是房间内的活动放置数，删除后可释放；墙饰也计入预算以防绕过。

不让家具通过 grind 解锁。目录新内容对成员可用；以后若做收藏，先验证它不会把朋友空间变成上线任务。

## 艺术方向与资产管线

基础是 CC0 的 **KayKit Furniture Bits**，外观扩展优先查看匹配其规格的 **Tiny Treats Homely House**。保留原作者、许可文本、固定版本与下载 hash，即使 CC0 不强制署名。Kenney 作为同条件比较对象；不要因为都是 CC0 就认为风格自动一致。[KayKit](https://kaylousberg.itch.io/furniture-bits)、[Tiny Treats](https://tinytreats.itch.io/homely-house)、[Kenney Furniture](https://kenney.nl/assets/furniture-kit)

建议艺术规则：蓝紫夜色、少量暖杏色主光、饱和度适中的植物与个人彩色点；统一家具比例与近邻纹理采样；阴影偏柔但边缘不要糊成一团。场景远处保持简单，灯光不平均照亮每一块墙。共造灯作为视觉焦点，个人窗提供第二层暖光。

像素风分为低像素密度、调色、轮廓与纹理四件事。原型低分辨率放大是第一件，不承诺复刻 Kind Words 2 美术。默认“gentle”档，用户可切清晰档；手机物体可辨认比更粗像素重要。

每个资产进入目录的步骤：

1. 核对作者页和许可，固定 source/version/hash；原始文件进入只读来源区。
2. 检查模型引用的纹理/缓冲是否齐全，限定资源大小；导出成生产 GLB 或规范化 glTF。
3. 定义单位尺度、地面 pivot、front 朝向、footprint 与允许 surface；3D 渲染与服务器规则读取同一逻辑清单。
4. 在标准房间里以四个方向、全部 variant、桌面与手机视图检查轮廓、穿模、遮挡、颜色和阴影。
5. 给小缩略图/可读名称、说明和来源记录；跑目录结构/引用/边界检查。
6. 旧存档用 `assetId + assetVersion + variantId` 重开；改 footprint 必须显式迁移或保留旧版本。

目录字段例子（设计示意，不能当作已验证的某模型真实占地）：

```json
{
  "assetId": "furniture.chair-a", "assetVersion": 1,
  "modelUrl": "/assets/chair-a.v1.glb",
  "surface": "floor", "footprintCells": [1, 1],
  "allowedYaw": [0, 90, 180, 270],
  "variants": ["natural", "sage"], "placementLimit": 30, "sockets": [],
  "sourceRecord": "kaykit-furniture-bits-1.0/chair_A",
  "licenceRecord": "assets/licences/kaykit-cc0.txt",
  "contentHash": "sha256:verified-at-build"
}
```

原型曾只校验可移动家具，导致植物穿入固定沙发。正式清单因此也包含墙、固定书架、不可编辑家具与室外禁放区，且服务端和前端共用定义；“不能穿模”不能只靠视觉预览。

渐进性能目标：初始只加载基础外壳和当前目录子集；共享 geometry/material；限制有阴影的灯与 shadow map；没有动画或状态变化时按需绘制，指针预览可临时连续渲染；后台页停动画。原型连续 RAF/235 draw calls 是验证实现，正式版应优化，但先以实测决定是否需要 instancing/合并，不为潜在规模重写整个引擎。

## 持续更新的规则

新增目录项只追加稳定 ID。已有名称可修正文案，已有 footprint/版本不悄悄改变。退休模型仍能解析旧存档，或给明确替代与迁移预览。新共同模板应首先复用作者拥有的 slot、贡献规则、修订、撤回和纪念版流程；如果不同模板需要复杂新权限，单独设计，不借“插件架构”隐藏问题。

未来的 16×16/8 色海报存储为有界像素数组；先验证总长度和色号，再生成纹理。它不需要任意上传服务，但仍可能包含冒犯图案，所以必须有隐藏/撤回机制。高级头像在确认骨架、动画兼容和剪切问题以后加入；先用完整预设能节省大量两周预算。

本文件与 [SYSTEM-DESIGN](SYSTEM-DESIGN.md) 不重复保存两套身份/事件规则。此处定义用户承诺，系统文件定义如何落实；[交付与验证](DELIVERY-AND-VALIDATION.zh-CN.md)把两者映射到测试和实际试用。
