# 夜间居民区：交付、验证与继续开发

2026-10-06。相对开发日按约两周个人开发预算规划。不是官方截止时间，也不是已经完成的开发报告。

## 先建立真实基线

正式 A3 仓库目前未确认。拿到链接后检查真实 working tree、AGENTS/CLAUDE、包清单/锁文件、课程 provision、`fly.toml`、Docker、CI、`spec/` 与证据检查脚本。不要把本研究目录初始化为假课程仓库，也不要覆盖已有模板/未提交改动。

本地研究原型只有Three.js0.186.1、npm、演示身份、SSE和JSON存档。生产优先考虑NodeLTS/TypeScript/Express/HTTP+SSE授权全量快照/better-sqlite3；实际模板已有合适栈则先比较保留成本。Socket.IO增量/屏障协议是有具体需要时的后续选项。生产版本在实际安装/构建之后锁定，不能把文档里的框架名当作已安装依赖。

D1 即核验生产 SQLite 实际引擎版本、目标 Linux 原生模块构建和 Fly 卷挂载。不要拖到最后一天才发现数据库写在临时文件系统，或 `release_command` 不提供卷。[Fly 配置](https://docs.fly.io/reference/configuration/)、[SQLite WAL 修复说明](https://sqlite.org/wal.html)

## 评阅者如何进入

`/readme/`全文之外提供“我有邀请”入口。评阅前在同一居民区**预留两个独立名额**，主持人生成两份覆盖评阅/次日重访窗口的单次邀请，通过课程认可的提交/访问说明渠道私下交付；不写进公开Git、CI或日志。本研究未发送邀请。两个新会话各自兑换为真正不同的居民并保存恢复码，随后直接操作，无须再次联系开发者。正式A3提交渠道到位后核实交付方式和有效期。

评阅期试用成员最多6位以留2个名额；用合成/低敏感度内容并告知朋友评阅者会成为成员。满员不能绕过8人限制，主持人评阅前完成准备。评阅后显式移出评阅身份、撤销剩余邀请、收起其内容。只读demo用于外观预览，不能充当多人写入验收。D1–2就试走两份邀请，不拖到最后。

## 测试层次与行为

**领域单元测试**用于可重复的放置、版本和归属规则。生产行为遵循 red–green–refactor：先通过有意义的失败例子证明缺口，再实现和检查。使用实际项目覆盖工具，目标至少80%相关代码覆盖，但覆盖率不能替代重要边界；文档和素材清单使用原生校验，不为 prose 编造单元测试。

**集成测试**使用真正SQLite临时数据库和真实HTTP/SSE（选Socket.IO时检查该路径）。只对启用的Core或Full合同宣称完成；延期档案/旗块不建表，也不声称相关检查通过：

- 重复同 UUID + 同 payload 返回原回执；同 UUID 改 payload 拒绝；commit 成功 ACK 丢失仍只修改一次。
- 两人各改自己 slot 可成功；两标签页同 entity revision 只有一个成功，另一端收到冲突并重取详情。
- 房主、其他成员、被移出成员和 demo 路径的权限不同；invite 不能凭空恢复旧身份。
- 把鉴权后的服务端数据库状态变化纳入每次 mutation 检查，不能只在建立连接时校验。
- 快照版本与增量有确定边界；漏序号、最后一个消息丢失、重连历史过旧，都最终重取快照。
- 未提交事务不广播；数据库忙/磁盘满/迁移失败有清楚错误，没有虚假“保存成功”。
- 作者撤回/退出更新实时对象、档案、事件载荷与缓存；其他人的贡献仍在。
- 旧目录版本和变更 footprint 存档能打开；未知 asset/超大像素数组/非法文本请求被拒绝。

**浏览器端到端**用两个独立 browser context，而非同 cookie 的两页冒充不同安全身份：邀请、领取窗、布置、共同灯、重访、纪念版、撤回、重连、键盘与手机布局。测试最终结果来自 UI → API → DB → 远端 UI；build 通过只说明能构建。

**运行与设备**：真实小 Fly Machine 上测10–20次明确动作的跨会话时间，记录命令 ID、提交/发送/远端呈现时刻和网络条件；以课程约1s为操作目标，不拿本地SSE一次观察当服务保证。记录真实手机型号/浏览器/DPR、冷/暖缓存、有效场景大小、内存或可用诊断、掉帧和触摸体验。若只获取RAF/CPU时间，说明没有GPU完成时间。

**故障演练**：本地重复命令、服务重启、生产卷存档重部署、数据库在线备份与新文件恢复、资产404、WebGL不可用/context-loss、邀请撤销、cookie丢失/恢复码、过期事件历史。每次说明真实故障还是模拟开关，未执行项保持 pending。

## 已做的对照与后续实验

研究阶段冻结了[三候选协议](../../evaluation/visual-comparison-protocol.json)，比较同场景固定与轨道3D、二维等距可行性、像素档位。实际记录在[RESULTS](../../evaluation/RESULTS.zh-CN.md)。二维资产不同，手机是CSS视口，场景很小，因此结果只能支持这个范围的可行性。

独立 agent 初次读取匿名候选，发现裁剪证据无效，初次视觉排名撤回；修正为完整截图之后明确作为不匿名的复审。反向顺序的第二位审查保留资产研究背景，不能声称两个都完全无历史。这个方法上的失败应写入过程证据，不能为了漂亮结果隐藏。

正式产品还需三个低成本、决策相关的体验比较，按顺序而非同时上线全部实验：

| 问题 | 两种方案 | 控制与任务 | 决策依据 |
| --- | --- | --- | --- |
| 第一次是否理解共同制作 | 先布置自己的窗 vs 先给共同灯添一片 | 同一个熟人小圈子概念、同样选项和时限，交替先看顺序 | 用户能否解释归属与下一步、需要几次帮助 |
| 贡献是否有共同目的 | 纯调色灯 vs 有真实 occasion/title 的共同灯 | 一件同样的灯，不改渲染质量；不制造虚假生日/事件 | 自己会留下什么、回来想看什么、是否感觉被要求 |
| 手机上编辑是否顺手 | 页面下方长表单 vs 所选对象底部短操作面板 | 同样的移动/旋转/撤销任务，反向顺序 | 完成动作、寻找困难、误触、滚动次数和口述偏好 |

这些是小样本可用性/概念比较，不是有显著性、能估算留存的线上统计 A/B。要真正测保留率需要更大样本、时间与事先分析计划，初版不做那种承诺。

## 真实朋友试用

首6h先用现有原型/故事找2位朋友做约10min的“纯调色 vs 真实场合”概念检查，先确认共造的意义，再投入第二模板/档案。正式试用邀请4–6位已认识彼此的自愿参与者，用真实低敏感度场合。第一回合约15–20min，无开发者代操作进入/布置；包含 **两人同时做同一盏灯，看到对方变化后调整自己的部分，并解释一起做与独自做的区别**。隔天再约10min：自行回来、找变化、修改/撤回、访谈。即时共造和隔时接续分开记录；时间随参与者调整，不强制全员同一时段上线。

记录任务是否完成/在哪里需要帮助、误解与引用原话、哪个动作有意义、是否感觉欠别人一次贡献、第二次来真正想看什么、手机/键盘障碍。身份以匿名编号记研究笔记，不记录私人注释内容到技术日志；对录屏/引用分别取得同意。结果以案例与主题写，不能用4人的比例推断所有朋友。

停止/修改某个机制的实际信号：多数人只能说“很好看”但不知道为什么留下东西；个人贡献被误认为别人可随便改；成员担心不参与会被看到；手机核心动作找不到；撤回以后旧纪念版仍能看见原文。先修核心，后加家具。

## 评审和证据管理

每一轮先给审查者 bounded task、冻结材料、具体标准和停止条件。探索/评审只读；worker 拥有明确文件；父 agent 整合而不是把多数意见当真。无历史审查使用新的 fork 时明确声明，已有子任务背景则披露，不伪装成完全独立。

工程审查优先 correctness、权限、回归、重要缺测；产品审查优先完整流程、实际价值、手机和不必要负担。修复必须能指向文件/行为，复测受影响部分；通过后不为次数而反复跑同样测试。

沿用 A2 的需要→观察→选择→检查→提交证据格式。引用真实 commit/compare 链接，不补造开发历史；本目录不是Git仓库，现阶段只有实际文件、工具输出与实验记录。A2 原有结果和reflection只是方法参考，不能写成A3过程。[继承记录](../../reference/INHERITANCE.md)

发布前准备具体可审查的版本、改动清单、许可/秘密检查、课程检查、截图与回滚步骤。写本地文件/修复/草拟在当前授权范围内；push、公开发布、付费服务和第三方更改按已有明确授权执行。这个研究请求没有触发公开发布。

## 维护与更新节奏

首版后先用1–2周修复真实问题；每次只加一个内容包或一个共同模板，并检查旧存档、目录引用、权限/撤回和两视口。保留小而明确的 changelog 与 schema/catalog migration。无须预先做 marketplace、微服务或插件平台。

运行检查关注数据库锁等待/容量、命令失败类别、恢复次数、提交到广播耗时、模型加载失败与启动健康；不收集在线时长排行榜。备份策略、期限和负责人进入具体运行记录，备份恢复实测后才称“可恢复”。单机有维护停机，启动提示真实状态。

目前的交付是 **研究、局部原型、经过审查的设计计划**。下一阶段的完成条件是上述能力在真实 A3/Fly 环境里成立并有真人反馈；两个阶段的证据不能混用。
