## 原始构想

网站是一栋小楼，每个朋友拥有一扇窗。大家进入同一个空间，可以主动点亮自己的窗、摆一件小物件、留一张便签，或者给朋友的窗台送一杯虚拟咖啡。变化实时出现；离开再来，布置、便签与礼物仍然保留。

目标用户是异地朋友、家人或毕业后分散在不同城市的小群体。核心体验是轻量的共同在场：人可以停留、留下痕迹，也可以安静离开。项目形式是陪伴空间；是否让人感到温暖，需要实际试用判断，不能预先声称它改善了关系。

## 拟议的两周扩展版本

保留小楼和窗台的核心，扩展成一个完整、可恢复的共同空间：

- **邀请与身份恢复：** 创建小楼、邀请朋友、认领窗户；回来仍能找到自己的空间。身份方式尚未选择。
- **个人布置与权限：** 从有限物件目录调整窗台、颜色与摆放位置；只有主人能修改自己的布置。
- **实时共同状态：** 同步布置、便签、礼物和主动展示的灯光；显示连接状态，断线后取回当前状态。
- **便签与礼物：** 便签可修改或删除；礼物保留赠送者、收件人和简短文字，收件人决定是否展示。
- **共同档案：** 大家主动保存某一刻的街景，留下精选快照和说明，之后可以回看。

扩展的重点是把同一栋楼住完整。物件目录先做少量精心设计的内容，档案先做静态快照。

## 核心流程与最小可用版本

创建小楼 → 邀请朋友 → 各自认领窗户 → 主动亮灯 → 布置窗台或留下便签 → 给朋友送礼 → 下次回来继续使用。

最小版本让两个人拥有各自的窗户：一人摆物件、留便签并送礼，另一人的页面自动更新；双方重新进入后仍可看到保存内容。做到这一条完整流程，再增加目录、档案与视觉细节。

## 保存什么，暂时显示什么

| 状态 | 拟议处理 |
|---|---|
| 小楼成员、窗户归属、布置、便签、已接受礼物、主动保存的快照 | 持久保存，跨会话恢复；服务器重启或重新部署后的保留需要验证 |
| 当前连接、临时编辑提示、未保存的拖动预览 | 暂时显示，断线后清理或重新取得 |
| 主动点亮的灯光 | 暂定作为当次停留状态，退出或超时后熄灭；具体规则待定 |

灯光由本人主动展示，不自动等同于真实在线状态。不默认记录最后上线时间、停留时长或个人活动轨迹，避免共同空间变成朋友之间的监视工具。

## 什么才算“好”

可测试的承诺：两名成员的有效修改约一秒内同步；朋友不能改别人的窗台；断线重连不会丢失已确认的修改；同时送礼不会重复生成；手机上能完成认领、留便签和收礼；保存内容经重启后仍存在。

需要人判断的部分：打开时是否愿意停留，礼物是否有意义，是否产生回复压力，视觉和动作是否让人感到朋友在附近。试玩应记录具体观察与反馈，不能把同步成功当作陪伴效果已经成立。

## 两周范围与待定事项

第 1–3 天做通最小流程并部署；第 4–8 天完成权限、重连、布置与便签礼物；第 9–11 天做精选档案和手机体验；第 12–14 天找朋友试用、修复问题并整理过程证据。

主要风险是美术与动画扩大工作量，以及即时状态与保存状态混淆。身份恢复、邀请失效、退出成员的窗户、便签可见范围、礼物接受规则与灯光超时方式，需要在实现前决定。技术栈尚未选择。
