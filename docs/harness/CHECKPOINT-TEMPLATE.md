# A3 subsection checkpoint template

Use one entry per substantial capability/failure path. Group adjacent entries only
when each retains its own findings/evidence. Owner-required throughout all phases.

- ID / phase / section / subsection / date / responsible agent.
- Owner/course requirement and concrete user task.
- Current commit plus dirty source hashes where necessary; dependencies and freeze.
- Applied report/method sections actually reopened at this checkpoint.
- Invariants and important normal, failure, concurrent and recovery paths.
- Current observation; documented fact/inference/proposal distinguished.
- Decision question and alternatives; what observation would change the choice.
- Selected method: technical/design/agent A/B/human comparison/correctness check.
- Common task/input/environment; candidate mapping, criteria and stopping condition.
- Research sources with owner/date/version/section/access/limit/implementation consequence.
- Actual commands/artifacts/exits/state; PASS/FAIL/NOT RUN/ABORTED/INFRASTRUCTURE FAILURE/CALIBRATION classification.
- Independent reviewer context and scope; findings and evidence.
- Parent verification/reconciliation, correction and affected rerun.
- Acceptance/current status; remaining gap and next concrete action.
- Actual commit/compare link; future-maintenance consequence.

For a retrospective revisit, say so and distinguish old evidence from checks run
now. If comparison is unnecessary, give the decision-specific reason. An unresolved
consequential choice requires investigation, not a generic waiver.
