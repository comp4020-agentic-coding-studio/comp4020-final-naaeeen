## Continuous evidence-driven methods

These are owner-required defaults for substantial research, design, implementation
and evaluation. Apply them to each phase, section and meaningful subsection,
returning to the applicable research, comparisons, reviews and evidence records
at entry, after findings or changed assumptions, and before accepting the result.
Do not substitute four aggregate checks for detailed work.

- Use credible alternatives and controlled comparisons frequently. When a material
  decision has plausible alternatives, define a common task, criteria, changed
  factor and stopping condition, then compare them. For agent/prompt/harness
  changes, use isolated matched A/B trials when their results can inform the choice.
- Require independent review for consequential plans, changes and boundaries.
  Start reviewers without previous chat history when supported; supply sufficient
  factual goals, constraints, source and rubric, excluding earlier verdicts or
  preferred winners. Verify their findings yourself, refine, and recheck. If the
  host has no independent reviewer, label self-review and actual verification,
  independent review NOT RUN and the residual gap; preserve stricter project gates.
- Use relevant available skills and techniques proactively: research, prototypes,
  contract and failure-path checks, reproducible tests, real browser/device work,
  negative controls, calibrated evaluators and comparative trials. Open the
  matching skill and apply its useful parts critically; do not assume tools exist.
- Maintain an inspectable requirement -> evidence -> decision -> refinement ->
  verification trail per meaningful subsection. Distinguish technical comparisons,
  model judgement, fresh review, browser evidence and real-human A/B tests.
- For substantial work, use the personal `evidence-driven-work` skill at
  its discovered catalog path; otherwise check the actual host's user-skill
  location (normally `~/.agents/skills`). Load only applicable references. If
  unavailable, follow these defaults/project methods and report that limitation.
- Keep the method proportional: use techniques as often as they improve decisions,
  rather than optimising their count. A self-contained small answer or typo does
  not need a synthetic experiment. Record why a material comparison cannot run;
  do not fabricate trials, require unrelated rereading, or endlessly repeat green
  checks. Current user instructions and specific project rules still govern.
