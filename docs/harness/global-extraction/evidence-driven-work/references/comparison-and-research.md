# Comparison and research

Start with a decision, not a broad search quota. Inspect current project facts and
installed versions, then search diverse relevant sources/languages and read the
primary material. Sources inform imagination without becoming unquestionable rules.

For products, distinguish the reference's interaction/value from tools that supply
implementation and work still required. For APIs/assets/templates, check current
version, runtime compatibility, license, completeness and maintenance. A demo is
not a complete product. Separate source facts, inference and unverified hypotheses.

## Choose the comparison

| Question | Suitable method | Required boundary |
| --- | --- | --- |
| Library/architecture/resource choice | Matched technical spike/load | Same task, versions and resource conditions; record changed factors |
| Layout/camera/interaction | Matched design prototype/tasks | Same content, people, actions, viewports; mechanics separate from preference |
| Agent prompt/skill/harness reliability | Isolated agent A/B or ablation | Matched fixtures/model/effort/tools/scope; change guidance factor |
| Actual human comprehension/value/preference | Registered real participant comparison | Consent, order/coaching/baseline/metrics; model opinion is not participant evidence |
| A definite correctness defect | Discriminating failing repro/test | Recognise valid alternatives and reject the actual failure |

Before trials write candidates, common task/input, criteria, disqualifiers,
environment, trial/order plan, evaluator ownership, artifacts and stop conditions.
Freeze important workload/grader/source versions. Counterbalance presentation/order
where it can influence judgement. Hash/source-identify candidates when consequential.

Calibrate the evaluator against a plausible bad outcome and a legitimate valid
variant. Protect it from candidate edits. Inspect transcripts/outcomes instead of
hidden reasoning. Check for false PASS: wrong fixture, modified criteria, dropped
participants/connections, invalid generated input, stale binaries, incomplete flow,
screenshot wrapper versus actual glyphs, or changed environment/fonts.

Small trials are diagnostic unless stronger inference is supported. Preserve every
planned result, including failures, aborts and infrastructure faults. Do not rerun
until a preferred answer appears or discard negative evidence. Repetition is useful
for variance, calibration or relevant changes, not technique-count inflation.

If a consequential comparison cannot execute, give the actual reason, source-backed
provisional decision, a falsifier and the next feasible test. Keep the gate open.
A routine settled choice can use a focused check with a concrete reason; do not use
a generic exception to evade material comparisons.
