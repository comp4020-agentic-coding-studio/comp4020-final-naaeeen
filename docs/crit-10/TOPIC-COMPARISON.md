# Crit 10: selecting one argument

19 October 2026. The owner asked for an interesting, deeply reasoned reflection
rather than a feature checklist. This record compares explanations of existing
product choices; it does not invent a new implementation chronology.

## Common task and criteria

Explain a consequential choice in this house to another student in about 300
words. Every candidate must have a concrete user situation, two viable
alternatives, a capability sacrificed, inspectable implementation evidence and
an actual way the owner directed or corrected agent work. Prefer a decision that
reveals something about collaboration and supports a clear next action.
Stop when the strongest candidate's source claims and material counterexample
have been checked; agreement between agents is insufficient.

## Independent discovery

Three agents started with no inherited conversation (`fork_turns: none`). Each
received the same product goal, writing constraints and instruction to inspect
immutable baseline 6bbc4d2, not current Crit 10 drafts, prior verdicts or handoff.
They were asked to find up to two arguments independently. These were discovery
passes, not blind human preference tests or matched agent-performance A/B trials.
The parent did not supply the eventual preferred theme.

Agents A and B independently proposed both contribution/exit and identity topics.
Agent C's initial contribution question emphasized what a shared rewrite makes
“mine” mean. This convergence suggested where to inspect, but did not decide the
result. The parent read the cited store/HTTP tests and the source paths. The
selected argument has the clearest unavoidable cost: an export may preserve a
submission while losing the collaborative composition that made it useful.

## Refinement that changed the claim

The parent asked C to trace the ordinary export interface, not merely its API.
C found that an already-open standalone board offers personal export after
revocation, but reopening selects Admission without a former-board picker. The
embedded board also closes when membership is lost. The house archive download
covers rooms/cards, not board contributions. The parent checked these paths.

Consequently the reflection discusses a deliberate data/permission distinction,
not a completed right-to-leave experience. An exported object is an actor's last
submitted version, potentially containing earlier peer work; it is not proof of
exclusive authorship, a complete history or a self-contained image archive.
The next design task is an identity-scoped previous-house/export entry with clear
copy and separate permitted asset retrieval. That task is not silently added to
this local logging change.

## Research and evaluation boundary

[Caspi and Blau (2011)](https://www.openu.ac.il/Lists/MediaServer_Documents/PersonalSites/AvnerCaspi/Caspi_Blau2011.pdf)
is a primary study of psychological ownership in collaborative writing. It gives
language for a tension between personal and collective work; it did not test our
export design. Their 118-undergraduate Google Docs laboratory task measured
perceptions, not actual learning or actual product quality. The reflection uses
the concept, not their result as a claim about this house.

[Scott, Carpendale and Inkpen (2004)](https://cspages.ucalgary.ca/~sheelagh/wiki/uploads/Main/Publications/scott_cscw2004.pdf)
on personal/group/storage territories is a useful adjacent account for layout.
Its tabletop setting is less directly connected to retained contributions after
membership ends, so it is not the reflection's central reference.

No human trial or measured improvement in belonging, fairness or comfort is
reported. Browser rehearsal checks reachability and delivered state. A later
friend study should ask participants to predict both export contents after a
rewrite and how to retrieve them after leaving; confusion would challenge the
current compromise, even if every authorization assertion passes.
