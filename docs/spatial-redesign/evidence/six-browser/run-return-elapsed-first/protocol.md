## Cleanup and capture boundary

Each context is registered at creation. After the task checks, all owned context
close operations must resolve, their actual close events must occur, and none may
remain in the browser context list. Browser close must resolve with disconnected
state and zero contexts. Close errors, unresolved closes or remaining resources
invalidate a completed task. Source/protocol/runner/guard bytes are checked again
after cleanup. The final decision function checks frame history, current world
presence, cleanup and bindings together.

All raw captures, bodyText, full errors, navigation URLs and original PNGs go to
`.local/spatial-six-browser/run-LABEL`, verified git-ignored before any browser
starts. Tracked run directories contain protocol/runner copies and explicitly
whitelisted metadata, using error hashes rather than free-form error text. Failure
screenshots may contain an invite and therefore never enter tracked docs.

Ordinary evidence PNGs also stay local initially. Native pre/post capture checks
require a known invite, hidden title/lobby/House settings/code display and no
visible invite text or input value. No image is edited or redacted. After the
automation completes, original PNG inspection must verify six actual posed people
and chairs in the overview, required phone controls, and code-free approved views.
Only then may approved original bytes be copied to docs with matching SHA256 and
a separate inspection record. Automated success is
`PASS_VISUAL_REVIEW_PENDING`, after cleanup/bindings; it is not final native pixel
acceptance. This inspection is distinct from a human usefulness trial.

All mutations use native controls, mouse/touch/keyboard and ordinary Pause/Resume.
No forced clicks, DOM/game-state writes, fake socket frames, direct mutating HTTP,
security/OS setting changes or service operations are permitted. Authenticated
GETs and passive WebSocket copies are observations, not participation.
