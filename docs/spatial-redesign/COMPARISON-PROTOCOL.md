# Common task and design comparison protocol

This framework is frozen before the parent comparison and new independent design
review. Source collection and independent alternative discovery already began.
It is a structured design walkthrough, not a preregistered human A/B experiment.

## Common scenario

Six familiar friends share the same house. Two want uninterrupted independent
work; three want a brief shared activity; the sixth arrives late. Later all six
choose to participate. One participant leaves and reconnects. One person uses a
390x844 touch viewport; another uses keyboard/list controls. Existing bedrooms,
identities, work content and the independently usable board must survive a change.

Run these tasks against each candidate, including the current design:

1. Five friends start an activity and the sixth arrives. Each can see capacity,
   join/observe status and how to make a real contribution. Two players plus four
   watchers cannot be called six-player participation.
2. A person standing elsewhere attempts a new game action. It cannot change the
   table. An occupied seat plus explicit Join enables actions; standing/relocating
   withdraws eligibility. Passive viewing and exact historical receipt replay are
   distinct from starting a new effect.
3. Three take a break while two keep working. No whole-house forced switch,
   automatic sound, forced mode declaration or modal shown on other screens.
4. A sofa/rest user completes one useful named task that is different from merely
   sitting at the study table. Test its controls, ownership and ending.
5. Someone enters their bedroom with no desire to type a task or rearrange chairs.
   They can do something worthwhile. A later visit/return must have a clear purpose,
   not another route to their unchanged global card.
6. Someone leaves immediately, reloads and returns. Shared progress survives where
   promised; physical presence is not mistaken for renewed consent. Quiet and door
   permissions stay explicit. The keyboard/touch route must not require accurate
   3D raycasting to claim a legitimate seat.

## Criteria and evidence

Use named outcomes, not invented weighted scores. Record each task as supported
by a specified design mechanism, contradicted, or unresolved. Separate source facts,
our design judgment, a mechanical prototype and actual human observations.

Hard constraints: controlled avatars and owned rooms retained; up to six actual
contributors for the group activity; seat-bound new game mutations; voluntary
entry/exit; mixed intentions can coexist; standalone board access preserved;
privacy and original data retained; no unapproved provider/cost expansion.

Tradeoffs: concrete benefit, discoverability/mapping, route/modal burden, interruption
cost, visible capacity, recoverable consent, content effort, mobile fit, persistence/
security changes and approximately ten focused development days. That budget is an
estimate for planning, not measured execution time or a guarantee.

Counterfactuals: replace the furniture with a global button; remove any required
note/timer; try one quiet observer; try an offline reserved seat; compare the claimed
six-person game with a two-player game and spectators. Reject superficial repairs
that pass merely because an extra seat or form has been added.

## Review and stopping

Independent source audit, product-alternative discovery and source research start
without prior chat history. A later design reviewer receives factual goals,
candidates, source evidence and this rubric, excluding preferred winners/earlier
verdicts. Parent verifies actionable findings, revises and rechecks each affected
section. A follow-up by the same reviewer is contextual, not another fresh trial.

Stop when each proposed place has a testable task and lifecycle, significant
contradictions are resolved, scope/dependencies are explicit, and remaining human
questions have a runnable protocol. Do not run more identical model opinions or
unchanged application tests to manufacture confidence. A rejected/unresolved
alternative remains in the record.
